Getting started

Log in to the panel, understand what the M0 preview does, and how your credentials are protected.

What M0 is

The M0 preview proves one complete thread end to end: you log in, create a hosting account, a signed command goes to the privileged node agent, the agent creates the Linux user and its resource slice, the action is written to a tamper-evident audit chain, and the UI shows the account's live resource usage. Everything else — sites, mail, DNS, databases, backups — arrives in later phases.

Log in

  1. Open the panel URL your operator gave you (development default: http://localhost:5173).
  2. Enter your admin email and password.
  3. On success you land on Accounts.
Two-factor authentication (TOTP) is planned for P2 — the database columns already exist, enrollment UI lands with the identity phase.

How your session works

  • Passwords are stored with Argon2id — a memory-hard hash that is expensive to attack with GPUs. Plaintext passwords are never stored or logged.
  • Access tokens live for 15 minutes. The UI renews them automatically in the background using a refresh token that rotates on every use — a stolen refresh token stops working the moment the real session renews.
  • Lockout: after 5 consecutive failed logins the account locks for 15 minutes. Failed logins are audited.

Running it yourself (operators)

The full bring-up — PostgreSQL, control plane, root agent, key provisioning — is a copy-paste runbook: docs/runbooks/m0-fresh-vm.md in the repository. The panel control plane never runs as root and never touches the operating system directly; every privileged operation is a signed command that the Go agent verifies before executing.
