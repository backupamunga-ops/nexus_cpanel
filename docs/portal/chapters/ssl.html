SSL certificates

Every site can carry a TLS certificate — issued automatically via Let's Encrypt (ACME), or installed manually. The panel stores an encrypted copy for metadata and renewals; the node keeps the serving copy. Responses and screens carry metadata only — private key material never re-appears once stored (ADR-0009).

Issuing via ACME live in the panel

Open the site in Sites, find the SSL certificate card, enter the registration email, and press Issue via ACME. What happens next:

  1. the agent runs the full ACME v2 (RFC 8555) flow: account registration, order, http-01 authorizations;
  2. challenge tokens are written to the site's own document root (.well-known/acme-challenge/) so the running webserver — which owns port 80 — serves them; the agent never competes for the port, and the files are removed on every exit path;
  3. the agent confines the webroot to the hosting home root and validates it against planted symlinks;
  4. on success the certificate chain and key are installed on the node (key file mode 0600) and returned to the control plane, which stores them encrypted (AES-256-GCM) against PANEL_SECRET_KEY;
  5. the ACME account key persists on the node so re-issuance reuses the same Let's Encrypt account — rate-limit friendly.
dns-01 is still pending — the DNS write path now exists (B06: PowerDNS zones + records, ADR-0012), but the ACME client upgrade to dns-01 challenges is next in the queue. Until it lands the API refuses challenge_type: dns01 with a documented precondition instead of failing mysteriously, and wildcard certificates remain unavailable.

Manual installation live in the panel

Commercial or existing certificates install through POST /ssl/certificates with the domain, the certificate PEM and the key PEM. The node validates that the pair actually matches — different public keys are the classic outage, and that class of mistake is rejected before anything is written. Manual certificates are not auto-renewed: when they near expiry, install the renewed pair.

Renewal and revocation

  • ACME certificates — Renew re-runs issuance; the encrypted copy and last_renewed_at update together.
  • Revocation — removes the node files and the stored row; the audit chain records who revoked what, when.
  • Expiry visibility — the sites screen shows issuer and expiry; the cross-domain list (GET /ssl/certificates) feeds the expiry dashboard.

Key management

Two deployment secrets matter for SSL (see ADR-0009): CP_SIGNING_KEY_PATH (control-plane → agent command signing) and PANEL_SECRET_KEY (secrets at rest, ≥ 32 bytes of entropy). The panel refuses to encrypt or decrypt without the latter — a missing key is a hard startup error, not a silent default.
