Accounts & packages

Hosting accounts are the tenants of a node. Packages define what an account may consume. This page covers what works today (M0) and what lands with the identity phase (P2).

live in M0

Accounts today

  • List & inspect — every account with status, UID and home directory.
  • Create — see Your first hosting account for the full flow including what the agent does on the node.
  • Suspend / resume / delete — each action maps to a typed agent command and is hash-chained in the audit log.
  • Live usage — CPU time, memory and process count sampled from the account's cgroup slice and pushed over WebSocket. Disk usage joins when the filesystem category lands (P3).
P2

Packages & quota enforcement

In M0 every account is created on the bootstrap Default package — a seam so the flow works before package management exists. P2 brings the real thing:

  • Packages CRUD with quota JSON (disk, traffic, mailboxes, databases) and feature flags (PHP versions, shell access).
  • Account lifecycle completion: account.modify (rename, package change, shell), quota changes via account.quota — both commands are already registered on the agent and return a deliberate "not implemented until a later milestone" error today.
  • Access sharing: delegate account administration to other panel users without sharing your login.
  • Resellers with nesting, branding and session isolation.

Permission model

Every accounts endpoint declares the permission it requires (account:list, account:create, account:suspend, account:resume, account:delete, account:read) and the server enforces it on every request — the UI hides what your role cannot do, but the API is the real boundary.
