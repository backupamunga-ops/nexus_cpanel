DNS zones

Authoritative DNS via PowerDNS on the node. The panel never edits zone data itself — every change goes through the privileged agent to the PowerDNS API, bumps the SOA serial, and lands in the hash-chained audit log. PowerDNS is the single authority; the panel keeps a mirror for listing and permission checks (ADR-0012).

Zones live in the panel

Open DNS, pick a hosting account, and create a zone. Two seeding paths, both explicit:

  • With a seed IPv4 — the zone is created with an @ A record pointing at the address you entered plus a www CNAME; the panel never guesses the server's address for you.
  • With no seed — the nameserver seeds a conventional SOA (ns1.<zone>, hostmaster.<zone>) and the response tells you it did, so you can correct it if your NS plan differs.

Deleting a zone removes it from PowerDNS first (agent-first provisioning: a failed node call leaves the panel untouched) and then soft-deletes the mirror rows. Zone deletion is audited with who, when, and which zone.

Records live in the panel

Record types A, AAAA, CNAME, MX, TXT, SRV, CAA, NS. Names are relative to the zone (www, a.b, *.sub) or absolute with a trailing dot — an absolute name outside the zone is rejected, not silently relocated. The server shape-validates every value (IPv4/IPv6 parsing, hostname shape, MX priority, SRV triple, CAA grammar, TTL 60–604800) and the nameserver validates again — errors from PowerDNS surface verbatim.

Every add/edit/delete is one full-set diff against the live zone: the panel recomputes the desired record set, the agent diffs it against PowerDNS's current state, and one patch applies the result. This means out-of-band edits made directly inside PowerDNS are reconciled by your next panel save instead of silently diverging. The SOA rrset is never touched by record edits — the serial is owned by the nameserver (soa_edit_api=DEFAULT bumps it on every patch, so secondaries and caches track changes).

DNSSEC live in the panel

Enable DNSSEC runs pdnsutil secure-zone and shows the resulting DS record — exactly the string your registrar needs — plus the zone's DNSKEYs. If the keys were generated but no material appears, the command fails loudly instead of reporting a secured zone. The DNSSEC card always shows live node state; if the panel's flag and the node ever disagree, the card says so.

Private keys stay inside PowerDNS's own store. Archiving exported key material into the panel's encrypted vault (dnssec_keys) is planned — the honest state today is "keys live on the node; the panel surfaces the public material."

Checks and export live in the panel

  • Zone check — pdnsutil check-zone, findings shown verbatim; [Error] lines flip the verdict.
  • Propagation check — for every A/AAAA/TXT/CNAME record the panel queries public resolvers (1.1.1.1, 8.8.8.8 by default) and reports per resolver: match, mismatch, missing (no answer yet), or timeout. Nothing is flattened into a single fake "propagated ✓". This runs in the control plane on purpose (ADR-0012) — asking resolvers is not a privileged node operation.
  • Export — the zone in AXFR transfer format, ready for BIND-style import elsewhere.

Node configuration

The agent talks to PowerDNS over its local HTTP API. Configure once per node:

  • NEXUSAGENT_PDNS_API_URL — default http://127.0.0.1:8081/api/v1;
  • NEXUSAGENT_PDNS_API_KEY — the API key; without it, dns commands fail with a documented precondition instead of pretending;
  • NEXUSAGENT_PDNS_SERVER_ID — default localhost.
Not yet built (honest list): zone templates and BIND file import (the API spec's /dns/templates and /dns/zones/{id}/import — the export side is live), secondary-DNS/AXFR serving, reverse-DNS handling, and dns-01 wildcard certificates (the write path exists now; the ACME client upgrade is next). The dnssec_keys table is pre-laid but unwired — see the DNSSEC note above.
